## 本次发现并修复的 Bug 清单

### 🔴 严重 Bug（影响基本功能）

#### Bug 1：JWT Secret Key 每次重启都随机，用户Token立即失效
- **位置**：`backend/app.py` Line 13-14
- **问题**：使用 `os.urandom()` 生成密钥，每次后端重启后所有已登录用户的 JWT Token 立即失效，必须重新登录
- **修复**：改为固定密钥字符串

#### Bug 2：历史记录路由冲突 `/all` 被解析为 `<int:task_id>`
- **位置**：`backend/history_routes.py`
- **问题**：Flask 按注册顺序匹配路由。`/<int:task_id>` 注册在 `/all` 之前，导致访问 `/api/history/all` 时 Flask 尝试将 "all" 转换为整数，返回 404 或 400
- **修复**：重新排列路由顺序，将 `/stats` 和 `/all` 移到 `/<int:task_id>` 之前注册

#### Bug 3：本地文件浏览 API 无身份验证（安全漏洞）
- **位置**：`backend/files_routes.py`
- **问题**：`/api/files/local` 接口没有 `@jwt_required()` 装饰器，任何人无需登录即可浏览服务器上的任意目录，存在严重目录遍历安全风险
- **修复**：添加 `@jwt_required()` + 路径合法性检查（防止 `../` 目录穿越）

#### Bug 4：前端文件浏览使用原生 fetch 不携带 Token
- **位置**：`frontend/src/views/Files.vue`
- **问题**：`loadLocalFiles` 函数使用原生 `fetch()` 而非项目封装的 axios 实例，不会自动附带 JWT Authorization 头，导致已登录用户访问本地文件时返回 401
- **修复**：改为使用 `api.get()` （axios 实例），统一走请求拦截器添加 token

### 🟡 中等 Bug（影响正确性）

#### Bug 5：NewestStrategy 当远程 mtime=None 时比较崩溃
- **位置**：`backend/sync_engine.py` `NewestStrategy` 类
- **问题**：FTP 服务器扫描时远程文件的 `mtime` 字段始终为 `None`（FTP LIST 命令不提供精确时间戳）。`NewestStrategy.should_sync()` 直接用 `local['mtime'] != remote['mtime']` 比较，当 remote['mtime'] 为 None 时逻辑正确，但 `get_direction()` 中的 `local['mtime'] > remote['mtime']` 会抛出 `TypeError: '>' not supported between NoneType and float`
- **修复**：添加 None 检查，当远程 mtime 不可用时降级为大小比较

#### Bug 6：Windows 路径下文件名用 `/` 分割导致错误
- **位置**：`backend/scheduler.py` `_save_history` 方法
- **问题**：`result['file'].split('/')[-1]` 在 Windows 路径中（如 `fileB.txt`）虽然偶然能工作，但当路径包含 `\` 时会返回整个路径作为文件名
- **修复**：改为 `os.path.basename()` 正确跨平台处理

### 🟢 优化项

#### 优化 1：list_tasks 获取远程大小导致性能问题
- **位置**：`backend/sync_routes.py` `get_remote_folder_size()`
- **问题**：每次获取任务列表都为每个任务建立新的 FTP 连接计算远程文件夹大小，超时设置为 5 秒，多任务时可能导致前端请求挂起数十秒
- **修复**：超时降至 3 秒，添加 `cwd` 切换到实际远程路径再统计（原代码只统计根目录）

#### 优化 2：watchdog 监控过滤无关文件
- **位置**：`backend/watcher.py` `SyncEventHandler`
- **问题**：`.pyc`、`.tmp`、`.swp`、`~` 等临时文件的变化也会触发同步，产生大量无意义的同步操作
- **修复**：添加 `IGNORED_EXTENSIONS` 和 `IGNORED_PREFIXES` 过滤，事件处理前先检查

#### 优化 3：同步结果返回更多信息
- **位置**：`backend/sync_routes.py` `manual_sync()`
- **改进**：返回 `synced_count` 和 `error_count` 字段，前端可以区分全成功/部分失败两种情况
